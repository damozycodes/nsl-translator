# GitHub and Render deployment

## Push

Create an empty private GitHub repository, without an autogenerated README.
Run from the project directory, replacing YOUR_USERNAME:

```sh
git add .
git diff --cached --stat
git commit -m "Prepare NSL translator for Render"
git remote add origin https://github.com/YOUR_USERNAME/nsl-translator.git
git push -u origin main
```

If Git asks for your identity, set `git config user.name` and
`git config user.email` locally first. No credentials belong in these files.

## Render

Choose **New > Blueprint**, connect your GitHub repository, and select `main`.
Render reads `render.yaml`; review and apply its proposed resources. It specifies
one paid 1 CPU / 2 GB service and a paid 5 GB disk. This is an initial configuration,
not a measured capacity guarantee; monitor memory during stickman rendering.
Render uses the Dockerfile, not Compose. No manual start command is needed.

The image installs requirements-runtime.txt and the spaCy English model.
TensorFlow and training-only packages remain in requirements.txt for local
research, but are not installed in the deployment image.

## Upload the dataset once

Git deliberately excludes recordings and landmarks. Until they are transferred,
the server can be healthy while recorded-sign translation remains unavailable.

On your Mac:

```sh
sh scripts/package_dataset.sh
```

Add an SSH public key to your Render account. Copy the SSH destination from the
service's **Connect > SSH** menu. Replace RENDER_SSH_DESTINATION below with its
`user@host` value (not the website URL):

```sh
scp tmp/nsl-runtime-data.tar.gz RENDER_SSH_DESTINATION:/app/dataset/
```

If using a dedicated key, add `-i /path/to/private-key` to the SCP command.
In the Render service Shell:

```sh
tar -xzf /app/dataset/nsl-runtime-data.tar.gz -C /app/dataset
ls /app/dataset
```

Confirm `clips`, `landmarks`, `manifest.json`, and `curation.json` are directly
under `/app/dataset`. Refresh the app. Do not regenerate the manifest from the
runtime-only dataset; training keypoints are intentionally absent.

Test a known word, original recording, stickman, illustrated fingerspelling, and
video download. The Streamlit health endpoint only verifies that the server runs.
Generated videos outside the dataset disk are temporary and can be regenerated.
Keep sentences short while checking the service's memory usage.

## Local Docker verification

Start Docker Desktop, then run:

```sh
docker compose config --quiet
docker compose up --build -d
docker compose logs -f
```

Open http://localhost:8502 (separate from your existing local app on 8501).
Compose mounts the existing local dataset read-only and keeps generated outputs
in a named volume. It targets linux/amd64 to match Render; Apple Silicon builds
use emulation and may be slower. Stop with `docker compose down`.

## Updates

Push code changes to the connected branch to deploy them with Render auto-deploy
enabled. Transfer dataset changes separately. Keep original recordings, models,
and experiment results backed up outside Git.
